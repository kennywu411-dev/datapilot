# ADR 004：智能路由（Haiku 先答，按失败信号升级 Sonnet）

- 状态：已采纳（离线回放 + 实跑验证完成）

## 背景

E4 最终配置下，Sonnet 比 Haiku 高 4.4 个百分点（72.4% vs 68.0%），成本却是 14 倍。"智能路由"是上线前的一个缺口：能不能用接近 Haiku 的成本，拿到接近 Sonnet 的准确率？

## 决定 1：按运行时信号路由，不按难度标签

| 方案 | 优点 | 缺点 |
|---|---|---|
| 按 BIRD 难度标签分流 | 简单 | 标签是人工标注，真实用户提问时没有，生产用不了 |
| 先用分类器 / 小模型判断难度 | 可以提前分流 | 多一次调用；判断器本身要训练和评测 |
| Haiku 先跑，看运行信号决定是否升级 | 信号现成（纠错、报错、空结果、取值不存在）；不需要额外模型 | 看不到"执行成功但答错"的题 |

## 决定 2：三条规则事先定好，全部报告

- r1：触发过纠错就升级；r2：纠错用完仍有问题才升级；r3：r1 或 SQL 关联 ≥ 3 张表。
- 规则只看 (SQL, 调用次数, 轨迹)，离线回放和实跑共用同一个函数（`src/datapilot/routing.py`）。
- 升级时 Sonnet 从头独立重跑，不接着 Haiku 的结果改：两次互不影响，离线回放才能用已有的独立运行精确模拟。

## 决定 3：先离线回放，再实跑一次验证

- 回放（不花钱）：用 E4 的 3 组 Haiku / Sonnet 配对运行模拟三条规则（`route-replay-253ae6`）。
- 实跑（$0.23）：只跑回放里性价比最好的 r1（`route-r1-4bc570`）。

## 结果

| 方案 | EX | 成本 / 全 Sonnet |
|---|---|---|
| 全用 Haiku | 68.0%（3 次均值） | 7% |
| r1 回放 / 实跑 | 69.4% / 69.6% | 15% / 14% |
| r3 回放 | 69.9% | 34% |
| 全用 Sonnet | 72.4% | 100% |
| 理想路由（预知哪题会错） | 77.5% | 42% |

- 实跑与回放一致，回放方法可信。
- 路由只追回差距的 1/3 到一半：Haiku 的错题大多"执行成功、没有报错"，运行时信号看不出来。
- 理想路由能到 77.5%，说明两个模型错的题并不重合；下一步的提升空间在更好的"会不会错"判断器（如自洽性投票、结果合理性检查），而不是更多重试。

## 后果

- 新增 `RoutedPipeline`、`--models route --pipeline routed_r1/r2/r3`、`scripts/route_replay.py`。
- 服务层（问数界面）暂未启用路由：默认仍用单一模型。上线时把 `ChatService` 的模型工厂换成 `LLMPair` 即可。
