# ADR 001：数据来源与评测口径

- 状态：已采纳

## 背景

BIRD Mini-Dev 有两个官方下载源：HF `birdsql/bird_mini_dev`（只有题目）和完整包 minidev.zip（数据库 + 题目，2024-06）。两者题目不一致（问题日志 P1）。

主指标 EX 要能和官方公开数字（GPT-4 47.80 等）比较，评测器必须与官方 `evaluation_ex.py` 口径一致。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 直接调用官方脚本 | 口径天然一致 | 读写连接执行预测 SQL，模型生成 DROP 会毁库；只出汇总分，没有逐题状态；依赖 psycopg2 / pymysql |
| B. 自己实现，并与官方逐题对照 | 只读安全；有逐题状态（报错 / 超时 / 被拦截），方便失败分析 | 要证明口径一致 |

## 决定

- 题目与标准 SQL 用 HF 版，数据库用完整包。
- 采用方案 B：`src/datapilot/ex.py`，口径为 `set(pred) == set(gold)`，预测与标准共用 30 秒预算（先预测后标准），预测 SQL 一律走只读连接。
- 一致性证据：`scripts/official_crosscheck.py` 在三组输入上逐题对照，1500 次判分 0 处不一致（gold-check-d1190b）。
- 官方口径中的已知缺陷（重复行被忽略、慢标准答案恒判错、无 ORDER BY 的 LIMIT）保留不改，只在报告中说明，否则失去可比性。
