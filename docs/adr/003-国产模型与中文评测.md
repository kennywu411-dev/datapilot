# ADR 003：国产 API 模型接入与中文问题评测（v1.3）

- 状态：已完成。阶段 1：deepseek-flash 66.8%、qwen3.7-plus 68.0%；阶段 2：中英文无显著差别（Haiku 64→69%、Sonnet 77→72%）

## 背景

面向国内部署，有两处缺口：
1. 只有 Claude 三档和本地 qwen2.5-coder:7b（53.8%），没有国内公司实际在用的 API 大模型；
2. 卖点是"用中文提问"，但 BIRD 500 题是英文，中文只有 opspilot 库 15 题（全对，没有区分度）。

## 决定 1：接 DeepSeek V4 Flash 和通义千问（试跑后选 qwen3.7-plus），走 OpenAI 兼容接口

| 方案 | 优点 | 缺点 |
|---|---|---|
| 各用官方 SDK | 功能最全 | 多两个依赖，接口各不相同 |
| OpenAI 兼容接口，一个 `OpenAICompatLLM` 类 | 两家都支持；只用现有 httpx，不加依赖；换厂商只改配置 | 厂商特有功能要透传（`extra_body`） |
| 只接一家 | 省事 | 少一个对照 |

- 清单原写"DeepSeek-V3"：旧接口 `deepseek-chat` 已于 2026-07 停用，改用当前的 V4 Flash。
- 两家都选便宜档（与 Haiku 同档），回答"国内用什么、差多少、贵多少"。
- 结构化输出用 JSON 模式（`json_object`）：两家都支持，`json_schema` 支持情况不一；JSON 模式要求提示里出现 "json"，所以把 schema 附在 system 末尾。这是与 Claude 唯一的提示差异，结果里如实注明。
- 百炼显式关掉思考（`enable_thinking=False`）：思考模式输出价贵 4 倍；Claude 用的是 adaptive thinking，对比时注明。
- 只跑固定流程 E4（不接工具调用），与本地模型一致；runner 对 agent 流程直接拒绝。
- 缓存命中的 token 单独计价：DeepSeek 返回 `prompt_cache_hit_tokens`，百炼返回 `prompt_tokens_details.cached_tokens`。
- 价格先用第三方整理价（官方页面互相有出入），试跑 20 题后按控制台账单核对再改 `config.PRICING`；没有价格的模型 ID 拒跑，防止 `--max-cost` 失效。

## 决定 2：中文题集 = BIRD 分层抽样 100 题的中文问法

- 抽样用 runner 现有的分层抽样（seed=0），与本地模型的 100 题（qwen100-7e5bf2）是同一批，可以三方对照。
- 只翻译 question，evidence 保持英文：evidence 相当于业务口径文档，不是用户说的话。
- 专有名词（人名、卡牌名、帖子标题、赛事和活动名）保持库里的英文：中文用户也会这样输入。
- 常见类别词（颜色、性别、国家、语言、国籍、尺码、职位）译成中文，库里存的是英文或缩写。这 29 题标记"取值映射"，用来测"女性 → 'F'"。
- 注意：增强 schema 里本来就带取值说明（如 `gender: F: female`），部分题的 evidence 也直接给出取值，所以映射题不一定更难。分析时按"evidence 是否给出取值"分组看。
- 由英文原题翻译并逐条校对（`evals/zh100/校对表.csv`），由 `scripts/build_zh100.py` 生成题集；标准答案空跑 99%（唯一失败是 q701，标准 SQL 自身超时，与英文一致）。
- 实验：同一配置（E4）分别跑中文与英文同 100 题，Sonnet 为主、Haiku 验证，按题配对做 McNemar 检验。

## 后果

- 新增 `OpenAICompatLLM`（`src/datapilot/llm.py`）、`config.API_MODELS`、`scripts/build_zh100.py`、`evals/zh100/`。
