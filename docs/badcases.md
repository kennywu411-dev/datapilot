# Bad case

前三个案例来自 NL2SQL 评测，分别对应三种情况：标准答案错、标准答案的隐蔽 bug、模型真错；第四个来自 v1.6 的归因评测（真实数据）。都来自 Sonnet 最终配置 E4（`e4-3463b8`），细节见 `docs/failure/判定表.md`。

---

## 1. q115：标准答案把数字当字符串排序（标准答案错）

情境：问题是"南波希米亚人口最多的分行，男性客户占比是多少"。模型答 40.0%，标准答案 44.3%，EX 判错。

排查：我没有直接信 EX，而是把两边 SQL 都拿去执行，再看中间结果。标准答案写的是 `ORDER BY A4 DESC LIMIT 1`，A4 是人口数，但这一列在库里是 TEXT 类型。按字符串排序时，'93931' 排在 '177686' 前面（因为 '9' > '1'），所以标准答案选中了人口 9 万的地区，而不是 17 万的那个。模型写的是 `CAST(A4 AS INTEGER)`，选对了。

结论：模型对，标准答案错。我直接查了那个地区的人口数据，证实了这一点。

小结：EX 判错不等于模型错。这道题是标准答案把 TEXT 类型的人口数按字符串排序，选错了地区；要看中间结果才能发现。

判定方法：先写好判定标准，B 类（标准答案错）必须能指出标准答案违反了题目或 evidence 的哪一处，并用实际数据验证。50 道里 B 类有 28 道，比例和审计论文的 52.8% 一致，判定没有明显的系统性偏差。

## 2. q1243：COUNT 把 0 也算进去（标准答案的隐蔽 bug）

情境：问题是"55 岁以上病人中，凝血时间异常的人里女性占比多少"。evidence 给的公式是：异常且为女性的人数 ÷ 异常的人数。模型答 78.4%，标准答案 1.2%。

排查：1.2% 这个数明显不合理。标准答案的分母写的是 `COUNT(CASE WHEN PT >= 14 THEN 1 ELSE 0 END)`。COUNT 只跳过 NULL，不跳过 0，所以这个分母实际上数的是全部化验记录，而不只是异常的记录。模型用的是 `SUM(CASE … THEN 1 ELSE 0 END)`，和 evidence 一致。

小结：标准答案把 SUM 写成了 COUNT，而 COUNT 会把 0 也算进去，结果从 78% 变成了 1.2%。这种 bug 只看 SQL 很难发现，但看结果数值合不合理就能看出来。

对评测的影响：基准本身有噪声，所以报告同时给出 EX 和人工判定后的外推值（约 90%，区间 86–93%），并注明外推是估计，不是实测。

## 3. q892：选错了表（模型真错）

情境：问题是"得分最多的车手是谁"。标准答案用积分榜 driverStandings，得出 Vettel 397 分；模型用单场比赛结果表 results，得出 Hamilton 50 分。

排查："得分最多"通常指赛季积分，所以积分榜才是对的表。这个错误，值核对和执行纠错都抓不到：SQL 能正常执行，取值也都存在，错在语义上选错了数据源。

结论：这是当前系统抓不到的错误类型。下一步的改进方向是：遇到语义上可能混淆的表（积分榜和单场结果），在 schema 说明里写清楚两者的区别，或者生成多个候选 SQL，再比较它们的结果。

小结：50 道失败题里，模型真错的只有 2 道。其中一道是选错了表，这类语义错误靠执行反馈发现不了，需要更好的 schema 说明或者多候选投票。

为什么暂不做多候选投票：Sonnet 上的错误大部分来自标准答案和题目歧义，真正的模型错误只占失败题的 4%。投票会让成本翻好几倍，能提升的空间很小，先用数据算清收益再决定。


## 4. 归因 real-05：数据起点让"新老客"维度失真（方法的盲区）

情境：问题是"近 12 个月 GMV 比前 12 个月涨了，主要是什么带来的"。看板人工分析的结论是海外市场（同比 +12.1%，英国 +0.9%）和无编号订单占比上升。归因流程给出的第一原因是"新老客 = 老客"，占总变化的 573.8%。固定流程、自主 Agent、直接问数三种做法在这一例上第一原因全部没有命中（`attr-dev-3b5232`）。

排查：分解表里的数字本身没错，手写 SQL 核对过：老客 GMV 从 £6,143,490 涨到 £7,500,355，新客从 £2,187,851 跌到 £724,644。问题出在"新客"的定义，单据落在客户首单当月。数据从 2009-12 开始，前 12 个月里大量"新客"其实是早就存在的老客户第一次出现在数据里，看板的指标定义文档把这一条列为已知限制。所以"老客大涨、新客大跌"是数据截断造成的，不是经营上的变化。

为什么没拦住：流程用"历史上的正常波动"来压这种假象，但两个时间段各 12 个月、正好占满全部 24 个月，没有剩下的历史月份可以估计波动，折扣不起作用。

小结：分解算得对不等于归因对。维度本身的口径在某些时间段不成立时，再严谨的贡献度分解也会给出一个数字正确、结论错误的答案。能做的是把这类限制写进指标字典的维度说明，并在两段占满全部数据时提示"无法估计正常波动"；这两处目前都没有做。
